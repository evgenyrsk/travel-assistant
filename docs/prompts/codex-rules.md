# Переиспользуемые правила Codex

Эти правила применяются к задачам Travel Assistant, выполняемым через Codex или opencode.

## Контроль roadmap

- Перед изменением файлов прочитай текущий roadmap и релевантные milestones.
- Не переопределяй roadmap.
- Не меняй порядок этапов roadmap.
- Не начинай следующий этап без явного запроса пользователя.
- Если запрошенное изменение относится к будущему этапу, зафиксируй его в разделе `Рекомендации, не выполнены`.
- Обновляй содержимое roadmap только когда задача явно просит об этом и существует подходящий раздел roadmap.

## Контроль scope

- Держи каждую задачу маленькой, атомарной и проверяемой.
- Не расширяй scope только потому, что будущее улучшение кажется полезным.
- Не выполняй рекомендации в рамках той же задачи.
- Не трогай unrelated files.
- Предпочитай mock/stub providers, пока provider contracts и domain models не стабилизированы.
- Избегай захардкоженных допущений о внешних API, credentials и provider-specific behavior.

## Контроль документации

- Прочитай `README.md`, релевантные файлы в `docs/` и ADR в `docs/decisions/`, если они есть.
- Документируй public contracts до реализации или вместе с ней.
- Обновляй документацию, когда меняются поведение, архитектура, workflow или validation steps.
- Если ADR существуют, сохраняй изменения согласованными с ними.
- Если указанный путь к документу не существует, используй ближайший существующий документ и сообщи о расхождении.

## Отчетность

Финальные отчеты должны использовать этот формат:

1. Созданные файлы
2. Изменённые файлы
3. Краткое описание изменений
4. Принятые решения
5. Открытые вопросы
6. Рекомендации, не выполнены

Результаты проверки должны быть явными. Если проверка не запускалась, объясни почему.

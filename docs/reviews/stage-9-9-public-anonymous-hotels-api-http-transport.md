# Stage 9.9 — Транспорт для публичного Hotels API без авторизации

## 1. Цель и границы

Stage 9.9 добавляет внутренний HTTP-транспорт для будущих запросов к публичному
Hotels API. Транспорт проверяется только через Ktor `MockEngine`, не подключен к
композиции runtime и не выполняет реальные сетевые запросы.

Этап не добавляет подпись JWT, provider DTO, преобразование моделей,
autocomplete, оркестрацию поиска или вызов из `RealHotelOfferProviderAdapter`.

## 2. Что добавлено

### 2.1 Transport

`PublicHotelsApiHttpTransport` принимает внедренный `HttpClient` и
`HotelsApiTargetConfig` для публичной цели. Поддерживается один ограниченный
метод `postJson`:

- только относительный путь API без query и fragment;
- тело запроса JSON без преобразования;
- `Content-Type: application/json`;
- `Accept: application/json`;
- необязательный `X-User-Language`;
- отсутствие `Authorization`.

Для каждого запроса применяется `publicTarget.timeoutMillis`. Переданный
`HttpClient` должен содержать plugin Ktor `HttpTimeout`; Stage 9.9 не создает
HTTP-клиент или сетевой движок самостоятельно.

`HotelsApiHttpResponse` хранит только код состояния HTTP и исходное тело ответа.
Разбор ответа provider не выполняется.

### 2.2 Безопасность адреса

Транспорт отклоняет:

- абсолютный URL;
- сетевой путь вида `//host/path`;
- путь с query или fragment;
- путь без начального `/`;
- любой вычисленный адрес, у которого scheme, host или port не совпадает с
  настроенной публичной целью.

Вызывающий код не может передать произвольные заголовки через текущий контракт
транспорта.

### 2.3 Ошибки

| Условие | `HotelProviderErrorCategory` |
|---|---|
| timeout запроса или HTTP 408 | `TIMEOUT` |
| HTTP 401/403 | `AUTHENTICATION_FAILED` |
| HTTP 429 | `RATE_LIMITED` |
| HTTP 5xx или сетевая ошибка ввода-вывода | `UNAVAILABLE` |
| прочий ошибочный HTTP status или недопустимый путь | `UNKNOWN` |

Сообщение исключения содержит только безопасную категориальную формулировку.
Исходное тело ответа, URL, заголовки, конфигурация и детали исходной ошибки
ввода-вывода в сообщение не включаются.

## 3. Зависимости

Добавлены:

- `ktor-client-core-jvm` для основного типа транспорта;
- `ktor-client-mock-jvm` только для тестов.

Сетевой движок (`CIO`, Apache и другие) не добавлен. Поэтому runtime репозитория
не может создать HTTP-клиент для реального запроса из новой зависимости без
отдельного будущего шага.

## 4. Auth contract

Для Stage 9.9 принято уточнение владельца контракта:

- host поиска MVP — `https://hotels.tcsbank.ru/`;
- `POST /api/v1/hotels/search` вызывается без авторизации.

Выбранный Swagger формально задает корневой `SiamBearer`, а операция не содержит
локального `security`, то есть наследует корневое требование. Это остается
известным контрактным риском до проверки в sandbox. HTTP 401/403 поэтому явно
классифицируются как `AUTHENTICATION_FAILED` и не вызывают автоматический JWT
fallback.

Конфигурация private `JwtAuth` из Stage 9.8a не используется. `RS512`, разбор
ключа, подпись, refresh interval, добавление Bearer и кэш token не реализованы.

Swagger объявляет для поиска только необязательный `X-User-Language`. Заголовки
`x-source-platform`, `x-app-version` и `x-user-role` в этот транспорт не
добавлены.

## 5. Тесты

`PublicHotelsApiHttpTransportTest` проверяет:

- публичный URL, метод, тело JSON и media headers;
- наличие и отсутствие `X-User-Language`;
- отсутствие `Authorization`;
- блокировку небезопасного пути;
- преобразование HTTP 401, 403, 408, 429, 5xx и прочего 4xx;
- timeout запроса через `MockEngine`;
- безопасную сетевую ошибку без утечки деталей исходной ошибки.

Все ответы и ошибки синтетические. Реальные вызовы отсутствуют.

## 6. Совместимость

Не изменены:

- `Application.kt` и routes;
- `HotelOfferProviderFactory`;
- `RealHotelOfferProviderAdapter`;
- публичный API и OpenAPI Travel Assistant;
- frontend и generated clients;
- `FAKE` как provider по умолчанию;
- поведение hotel search и confirmation из Stage 7/8.

## 7. Ограничения

- Нет DTO запросов/ответов provider и проверки схемы.
- Нет оркестрации adapter и подключения к runtime.
- Нет проверки публичного host и анонимного доступа реальным запросом.
- Нет повторных попыток, журналирования или эксплуатационной наблюдаемости.
- `MockEngine` доказывает поведение транспорта, но не внешний контракт.
- Контракт autocomplete по-прежнему отсутствует.

## 8. Рекомендуемый следующий шаг

Stage 9.10 остается заблокирован до получения контракта autocomplete/location.
До Stage 9.11 также нужны решения по размещению гостей, возрасту детей,
nullable rating, `shownPrice` и обезличенному примеру ответа поиска.

Безопасный следующий шаг — получить контракт autocomplete либо выполнить
отдельную review-only проверку входных данных для Stage 9.10–9.11. Сетевой
движок, вызов sandbox и подключение к runtime пока не рекомендуются.

## 9. Verdict

Stage 9.9 завершает ограниченную границу HTTP-транспорта публичного Hotels API
без авторизации. Транспорт готов для будущего слоя DTO/orchestration после
подтверждения контрактов, но не подключен и не означает эксплуатационную
готовность real provider.
